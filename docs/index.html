⚡ Write Path (Atomic Local Vote + Cloud Firestore Sync)

1. User taps an option in Compose UI ➔ 2. viewModel.castVote(optionId) executes on viewModelScope ➔ 3. Room DAO commits an atomic ACID transaction to local SQLite (0ms latency, works offline) ➔ 4. Background Coroutine pushes the vote document to Cloud Firestore (polls/{id}/votes) ➔ 5. Cloud SnapshotListeners broadcast the new tallies in real-time to other participants.

💾

1. Hybrid Storage Engine

Room SQLite + Cloud Firestore

Instead of relying exclusively on the network, PulsePoll uses a two-tier cache:

  • 📦
    Local SQLite Cache (Room): Reads and initial writes hit the on-device SQLite database first. Guarantees 0ms UI response time and 100% offline functionality.
  • ☁️
    Cloud Firestore Relay: Asynchronous background sync sends updates to Firebase. Realtime WebSocket snapshot listeners sync results between multiple phones without needing a custom server backend.
🔑

Decoupled Architecture & Cloud Independence

Backend Portability & Zero Vendor Lock-in

LivePulse is built with strict Clean MVVM boundaries. While Firebase Firestore provides the default zero-config cloud relay, the data sync and authentication layers are fully abstracted behind Kotlin Repository interfaces. You can easily swap the cloud adapter for Supabase, AWS, or your own self-hosted server without touching the UI or local Room database.

Firebase Cloud Firestore (Default)

Zero Server Setup • Spark $0/mo

LivePulse uses Firestore as a serverless real-time document store. Snapshot listeners stream delta updates directly into Kotlin StateFlow with sub-100ms latency. No servers, Docker containers, or maintenance required.

Key Architecture Traits
  • ⚡ Sync Engine: Bi-directional WebSocket addSnapshotListener
  • 🔑 Auth Strategy: Google Sign-In (CredentialManager) + Meta + Apple + Guest
  • 💾 Local Cache: Room SQLite (Instant UI response + offline queue)
  • 💰 Cost: 100% Free on Spark Tier (50k daily reads / 20k writes)
FirestorePollRepository.kt KOTLIN ADAPTER 
// Firebase Firestore Realtime Stream Adapter
class FirestorePollRepository(
    private val db: FirebaseFirestore,
    private val pollDao: PollDao
) : PollRepository {

    override fun observePoll(pollId: String): Flow<PollWithDetails?> = callbackFlow {
        // 1. Emit local Room cache instantly (0ms)
        val local = pollDao.getPollWithDetails(pollId)
        trySend(local)

        // 2. Attach WebSocket listener for remote votes
        val listener = db.collection("polls").document(pollId)
            .addSnapshotListener { snapshot, _ ->
                snapshot?.toObject(PollEntity::class.java)?.let { remote ->
                    pollDao.upsertPoll(remote) // Updates Room & triggers UI Flow
                }
            }
        awaitClose { listener.remove() }
    }
}
💡 Replacing the cloud sync requires editing only this 1 repository file.
🛡️

1. Strict Repository Interface Contract

The UI (Compose) and ViewModels communicate exclusively through the PollRepository interface. No Firebase or Google imports leak into the UI or domain modules.

interface PollRepository {
  fun observePoll(id): Flow<PollWithDetails?>
  suspend fun castVote(optionId, persona)
  suspend fun syncPendingOfflineVotes()
}

2. Vendor-Neutral Local SQLite (Room)

Local state management uses standard SQLite and Android Jetpack Room. The app remains fully functional, responsive, and queryable with zero network connectivity or cloud credentials.

✓ Zero cloud locks: All vote totals, participant rankings, RSVP counts, and tiebreak math execute on-device in pure Kotlin algorithms.

Release Engineering & Operations

Production Deployment & Manual Setup

Complete end-to-end instructions, manual console setup, and automation scripts for deploying PulsePoll to Google Play Store and Firebase.

🔥

1. Firebase & Auth Setup

1. Create a Firebase project on the Spark Free Tier ($0/mo).
2. Register package com.aistudio.pollpulse.qxrvlz.
3. Enable Google Sign-In & Cloud Firestore.
4. Place google-services.json into /app.

🔐

2. Release Keystore & SHA-1

1. Run bash scripts/generate-release-keystore.sh.
2. Copy SHA-1 & SHA-256 certificate fingerprints.
3. Add fingerprints in Firebase Console ➔ Project Settings.
4. Configure signing in gradle.properties.

📦

3. Play Store Rollout (.AAB)

1. Run bash scripts/build-release.sh.
2. Locate bundle at app-release.aab.
3. Upload to Google Play Console Internal Testing track.
4. Promote to Closed Beta and Production!
