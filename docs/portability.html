🔄 Zero Vendor Lock-in

Backend Portability & Cloud Independence

LivePulse is built with strict Clean MVVM boundaries. While Firebase Firestore provides the zero-config default, the cloud relay is fully abstracted behind Kotlin Repository interfaces—ready to swap to Supabase, AWS, or Self-Hosted Ktor.

🔄 Pluggable Cloud Sync Adapters

Click a provider below to inspect how LivePulse adapts to different backend infrastructures:

🔥

Firebase Cloud Firestore (Default)

Zero Server Setup • Spark $0/mo

LivePulse uses Firestore as a serverless real-time document store. Snapshot listeners stream delta updates directly into Kotlin StateFlow with sub-100ms latency. No servers, Docker containers, or maintenance required.

Key Architecture Traits
  • ⚡ Sync Engine: Bi-directional WebSocket addSnapshotListener
  • 🔑 Auth Strategy: Google Sign-In (CredentialManager) + Meta + Apple + Guest
  • 💾 Local Cache: Room SQLite (Instant UI response + offline queue)
  • 💰 Cost: 100% Free on Spark Tier (50k daily reads / 20k writes)
FirestorePollRepository.kt KOTLIN ADAPTER 
// Firebase Firestore Realtime Stream Adapter
class FirestorePollRepository(
    private val db: FirebaseFirestore,
    private val pollDao: PollDao
) : PollRepository {

    override fun observePoll(pollId: String): Flow<PollWithDetails?> = callbackFlow {
        // 1. Emit local Room cache instantly (0ms)
        val local = pollDao.getPollWithDetails(pollId)
        trySend(local)

        // 2. Attach WebSocket listener for remote votes
        val listener = db.collection("polls").document(pollId)
            .addSnapshotListener { snapshot, _ ->
                snapshot?.toObject(PollEntity::class.java)?.let { remote ->
                    pollDao.upsertPoll(remote) // Updates Room & triggers UI Flow
                }
            }
        awaitClose { listener.remove() }
    }
}
💡 Replacing the cloud sync requires editing only this 1 repository file.
🛡️

1. Strict Repository Interface Contract

The UI (Compose) and ViewModels communicate exclusively through the PollRepository interface. No Firebase or Google imports leak into the UI or domain modules.

interface PollRepository {
  fun observePoll(id): Flow<PollWithDetails?>
  suspend fun castVote(optionId, persona)
  suspend fun syncPendingOfflineVotes()
}
💾

2. Vendor-Neutral Local SQLite (Room)

Local state management uses standard SQLite and Android Jetpack Room. The app remains fully functional, responsive, and queryable with zero network connectivity or cloud credentials.

✓ Zero cloud locks: All vote totals, participant rankings, RSVP counts, and tiebreak math execute on-device in pure Kotlin algorithms.
👥

3. Multi-Identity & Local Persona Support

Authentication is decoupled from a single identity provider. Users can authenticate via Google CredentialManager, Apple Sign-In, Meta Facebook SDK, or Instant Local Guest mode.

✓ In-App Persona Switcher: Switch between Alex, Sarah Connor, and Marcus Aurelius without logging out to test group voting on one phone.

Future Portability: Kotlin Multiplatform (KMP) Ready

Because all business algorithms (Quorum calculations, tiebreaks, RSVP counting, and short-code decoders) are written in pure Kotlin with zero Android framework dependencies, the core domain model can be exported directly to iOS (Compose Multiplatform) and Web (Kotlin/Wasm) with 90%+ code reuse.
