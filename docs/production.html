Production Deployment & Operations Runbook

This page is the condensed web view. The canonical, step-by-step guide lives in the repository: PRODUCTION_DEPLOYMENT.md.

Everything required to take LivePulse from development into Google Play Store distribution with Firebase backend setup and Google Sign-In authentication.

1

Firebase Console & Cloud Firestore Setup

100% Free on Firebase Spark Plan ($0/month)

1. Open console.firebase.google.com and click "Add project" (name it e.g. livepulse-prod).

2. In project settings, click the Android icon to register the Android app:

  • Android package name: Set to your applicationId from app/build.gradle.kts.
  • App nickname: LivePulse
  • Debug signing certificate SHA-1: See Step 2 below to extract your fingerprint.

3. Download google-services.json and place it in your app/ directory (e.g. /app/google-services.json).

4. In Firebase Console sidebar, go to Build ➔ Firestore Database ➔ Create database (start in Production mode, select your nearest region).

5. Under the Rules tab, paste the secure rules provided in our Distributed Defense Guide.

2

Keystore & SHA-1 Fingerprint Extraction

Required for Google Sign-In & Play Integrity

Google Sign-In uses OAuth 2.0 bound to the cryptographic SHA-1 fingerprint of your signing key. Run this command in your terminal or Android Studio:

TERMINAL (DEBUG KEYSTORE) 
keytool -list -v -keystore ~/.android/debug.keystore -alias androiddebugkey -storepass android -keypass android

Copy the SHA1: XX:XX:XX... string and paste it into your Firebase Project Settings ➔ Your apps ➔ Add fingerprint.

Google Sign-In also needs your OAuth Web Client ID (Google Cloud Console ➔ APIs & Services ➔ Credentials ➔ Web client). Put it in .env at the repo root — copy .env.example and set:

.ENV (REPO ROOT, GIT-IGNORED) 
WEB_CLIENT_ID=1234567890-abcdef.apps.googleusercontent.com
3

Release Keystore & App Signing

Required for a signed .aab and for Google Sign-In on release builds

The debug keystore only covers local testing. Generate an upload keystore with the helper script, then register its SHA-1 and SHA-256 in Firebase ➔ Project Settings ➔ Add fingerprint:

TERMINAL 
bash scripts/generate-release-keystore.sh

Signing secrets are read from environment variables (System.getenv in app/build.gradle.kts) — export them before building, and never commit them:

SHELL / CI ENVIRONMENT 
export KEYSTORE_PATH=/absolute/path/to/release.keystore
export STORE_PASSWORD='<your-keystore-password>'
export KEY_PASSWORD='<your-key-password>'

The key alias is fixed to upload in app/build.gradle.kts.

Signed bundles in CI: the release_bundle workflow job is opt-in — it stays dormant until you provide signing material. In Settings ➔ Secrets and variables ➔ Actions set:

  • RELEASE_ENABLED = true (Variables tab — the non-secret on/off switch)
  • RELEASE_KEYSTORE_BASE64 (Secrets tab — your keystore file, base64-encoded: base64 -i release.keystore -o release.keystore.b64, paste the output)
  • STORE_PASSWORD and KEY_PASSWORD (Secrets tab — must match the keystore)

On the next push to main/release/* (after tests pass), the pipeline decodes the keystore, runs ./gradlew :app:bundleRelease, and uploads the signed app-release-aab artifact. Play Store upload stays manual; flip RELEASE_ENABLED back to false to disable. Keep the original keystore safe and offline — losing it means you can never update the same Play Store listing.

4

Compiling Production Android App Bundle (.AAB)

Google Play Store Standard Release Format

Google Play requires new apps to be published as an Android App Bundle (.aab); Play then generates optimized APKs for each device configuration, so users download only the code and resources their device needs.

BUILD COMMAND (WRAPS ./gradlew bundleRelease + assembleRelease) 
bash scripts/build-release.sh

The script builds both the Play bundle and a standalone QA APK. The bundle artifact is generated at: app/build/outputs/bundle/release/app-release.aab.

5

Google Play Store Pre-Launch Checklist

Verify all launch standards prior to submitting
✅ Adaptive Icons Configured

Adaptive vector launcher icon in mipmap-anydpi-v26/ic_launcher.xml with foreground/background layers.

✅ Edge-to-Edge Enabled

enableEdgeToEdge() called in MainActivity.kt with WindowInsets scaffold padding.

✅ Minimum Touch Target Size

All interactive components adhere to Material 3 standard 48dp x 48dp clickable targets.

✅ Robolectric JVM Test Suite

17/17 Unit & JVM tests verified with ./gradlew :app:testDebugUnitTest (or bash scripts/run-tests.sh).

✅ Release Signing Configured

Upload keystore generated, its SHA-1/SHA-256 registered in Firebase, and KEYSTORE_PATH/STORE_PASSWORD/KEY_PASSWORD exported (Step 3).

6

Browser Access: Docs & Demo Site Hosting

Zero-Install Product Walkthrough on Any Device (Desktop, Mac, iOS, Chromebook)

The docs/ directory is a self-contained static site — this documentation plus an interactive, client-side demo of the poll-joining, voting, and RSVP flows. It makes no Firebase calls; real-time voting runs in the Android app with Firestore snapshot listeners. Host it on Firebase Hosting and share the URL with voters as a zero-install walkthrough.

TERMINAL (FIREBASE HOSTING) 
firebase init hosting   # public directory: docs
firebase deploy --only hosting
🌐 Zero-Install Walkthrough

Voters open the hosted URL in any browser and try the simulated demo — poll codes, voting, and RSVP flows — with no APK download or sideloading.

📱 Live Sync Stays in the App

Real votes, Room SQLite offline caching, and multi-user live sync require the Android app — the hosted site is documentation plus a simulated demo.
